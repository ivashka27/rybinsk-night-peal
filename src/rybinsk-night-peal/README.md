# Ночь на колокольне в Рыбинске

Ночью на колокольне в Рыбинске звонят по листкам. На листке записана партия: какие колокола бьют и как долго. Один удар — это номер колокола и число долей. Партия из двух ударов читается так: колокол 1 звучит две доли, потом колокол 3 звучит четыре доли.

Под удары каждого листка выделена своя память, и она принадлежит только ему. Сняли копию — у копии свой кусок памяти с теми же ударами, пометка на одном листе другой не портит. Отдали листок дальше — удары уходят вместе с памятью, у прежнего владельца остаётся пустая партия. Листок выбрасывают — память освобождается.

К утру звонарь не ставит листки в одну ленту друг за другом. Сначала он слушает, годится ли лист и нет ли в нём эха. Пустой перелистывает. Точную копию уже рассмотренного листа второй раз не звонит. Остальное складывает с ночью парами: на каждом месте встречаются два удара, а не две половинки подряд.

В программе листок называется `Peal`, один удар — `Stroke`. Колокольня слышит не всякий листок: сначала у него снимают голос, `voiceOf`. Ночь, `ringNight`, помечает каждый лист и складывает голоса уже не «друг за другом», а вперебор.

Листок и колокольня — разные правила. Листок хранит что написали, даже колокол 9 и нулевые доли. Колокольня такой удар не звонит. Если смешать эти два слоя, тесты разойдутся.

## Что нужно сделать

Писать нужно в трёх файлах.

`src/peal.cpp` — сам листок. Он умеет появиться, скопироваться, отдать память, принять чужой листок присваиванием, отдать удар по номеру и сказать сумму долей. Сложение `+` здесь не приписывает один листок к другому: удары встречаются парами. `+=` заменяет листок на эту пару и возвращает его же.

`src/voice.cpp` — функция `voiceOf`. Она решает, годится ли листок для колокольни, и убирает эхо. Исходный листок не трогает.

`src/night.cpp` — функция `ringNight`. На входе стопка, на выходе ночь: одна партия `played` и пометка `fates` на каждый листок. Стопка остаётся прежней.

Объявления методов уже стоят в заголовках, их не меняйте. Поля `strokes_` и `count_` тоже оставьте. Свой код можно держать в `.cpp` или добавить приватным методом в `include/rybinsk/peal.hpp`.

Проверка — тесты в `tests/`. Их стоит читать: длинный разбор ночи записан в тесте `night / вся ночь`, здесь его по шагам нет. Править тесты нельзя. Группы идут по порядку: `life`, `assign`, `ops`, `voice`, `night`. Ночь опирается на голос и на `+=`. Если время кончилось, сдавайте те группы, которые уже зелёные.

## Как запустить

Нужен компилятор с C++17 (g++ 7+, clang++ 5+) и CMake 3.16+. Из корня репозитория:

```bash
cmake -S . -B build
cmake --build build -j
./build/rybinsk_tests
```

То же самое одной командой: `make test`. Удалить сборку: `make clean`.

Без CMake:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -fsanitize=address -Iinclude -Itests \
  src/peal.cpp src/voice.cpp src/night.cpp \
  tests/main.cpp tests/test_life.cpp tests/test_assign.cpp tests/test_ops.cpp tests/test_voice.cpp tests/test_night.cpp \
  -o rybinsk_tests
./rybinsk_tests
```

Готовый прогон заканчивается строкой `итого: 32/32` и кодом возврата 0. На `main` написана только пустая партия, остальные тесты падают с текстом «ещё не написано». Так и задумано.

Сборка следит за памятью. Общий кусок памяти у двух листков, повторное освобождение и чтение удара из уже отданного листка приходят как красный тест.

Каталог `build/` и бинарник `rybinsk_tests` в git не кладите.

## Как устроен листок

`Stroke` — два целых числа: `bell` и `beats`. Листок не проверяет, есть ли на колокольне такой номер. Ноль и отрицательное число тоже можно записать. Свежий `Peal(n)` — это `n` ударов с нулями: колокол ещё не выбран и доли ещё не стоят.

Ниже точное поведение. На нём написаны тесты.

| Что происходит | Что получается |
| --- | --- |
| `Peal()` | пустой листок, `size() == 0`, памяти под удары нет |
| `Peal(n)` | `n` нулевых ударов; `n == 0` — пустой листок; `n < 0` — ошибка `PealError` |
| `Peal(p, n)` | копия `n` ударов из массива; при `n == 0` указатель может быть пустым; пустой указатель при `n > 0` и отрицательное `n` — `PealError` |
| копия | свои удары. Исходный листок можно менять и выбрасывать |
| перемещение | удары живут у нового владельца, источник пустой: `size() == 0`. Его можно выбросить и позже записать в него другую партию |
| деструктор | память освобождается. Пустой листок тоже спокойно выбрасывается |
| `a = a` | листок остаётся тем же |
| `a = std::move(a)` | листок остаётся тем же |
| `a = std::move(b)` | `a` забирает удары, `b` пустеет. Старая память `a` освобождается |

Текст `PealError` может быть любым. Тест проверяет тип ошибки. Если ошибка случилась у листка, который уже существует, его удары не меняются.

Сумма долей пишется как `static_cast<int>(peal)`. У пустого листка это 0. Четвёрка сама по себе листком не становится: `Peal p(4)` создаёт четыре нулевых удара, а запись `Peal p = 4` не компилируется.

Вот где обычно теряют удары.

В присваивании `a = a` слева и справа один и тот же листок. Освободите его память в начале — копировать будет неоткуда. Сначала проверьте, что это не один и тот же объект.

`a += a` считает новый листок, пока старый ещё цел, и только потом им заменяет. Если сначала освободить память, складывать будет нечего. Одинаковый листок сам с собой длиннее не становится: это правило перебора, не повод пропускать копирование.

После `b = std::move(a)` удары живут только в `b`. Если уход `a` освободит ту же память, `b` останется ни с чем.

Конструктор от массива удобно начать с `Peal(count)`: память выделяется в одном месте. Если элементов больше нуля, а указатель пустой, к моменту ошибки память уже может быть выделена. Деструктор её заберёт, объект к этому времени уже построен. Проверить указатель можно и раньше. При ошибке ничего не должно утечь.

## Как листки складываются вперебор

`a + b` — новый листок. `a` и `b` остаются как были. Пустой слагаемый ничего не меняет: в ответе копия другого.

Удары встречаются с одного и того же места: первый с первым, второй со вторым. Хвост того листка, который длиннее, дописывается в конец как есть и с уже сложившимися парами не перемешивается.

В одной паре:

- номера разные — сначала меньший номер, потом больший, доли у каждого свои;
- номер один — остаётся один удар, тот, что длиннее; при равных долях удар просто тот же.

Поэтому листок, сложенный сам с собой, не растёт: каждый удар встречается сам с собой. Пара решается только на своём месте. Листок `(5, 1), (1, 4)`, сложенный с `(3, 2)`, даёт `(3, 2), (5, 1), (1, 4)`. Удар `(1, 4)` остаётся в хвосте, хотя его номер меньше всех.

`a += b` заменяет `a` на `a + b` и возвращает сам `a`. В записи `a += b += c` сначала складываются `b` и `c`, потом это складывается с `a`. Пустой листок справа ничего не меняет.

Сложение не решает, годится ли колокол. Девятый номер в `+` живёт спокойно. Бракует его голос, не перебор.

`p[i]` — удар номер `i`, счёт с нуля. Его можно прочитать и заменить. Номер меньше нуля или номер от `size()` и дальше — ошибка, листок не меняется. У константного листка удар только читается.

`a == b`, когда ударов поровну и каждая пара совпала номером колокола и числом долей. Два разных листка с одной записью равны. Пустой равен пустому. `!=` означает, что листки различаются.

## Какой удар колокольня берёт

`voiceOf` смотрит на копию смысла, не на память листка. Листок после вызова тот же.

Удар годится, если это колокол с 1 по 8 и доли хотя бы одна, либо передышка: колокол 0 ровно на одну долю. Ноль долей, отрицательные доли, номер меньше 0, номер больше 8 и передышка не на одну долю портят листок целиком. Даже если плохой удар стоит вторым, голос пустой, а `accepted` — ложь. Свежий `Peal(n)` как раз из нулевых ударов, для колокольни он негодный.

Если все удары годные, эхо снимается. Пока передышки не было, второй удар в тот же колокол выбрасывается. Доли двух ударов не складываются: остаётся первый. Передышка память о колоколе стирает, и тот же номер может прозвучать снова. Две передышки подряд обе остаются.

Пустой листок принимается и даёт пустую партию. Это не брак.

## Как собирается ночь

`ringNight` идёт по стопке сверху вниз и на тестах не бросает исключений. На каждый листок одна пометка, в том же порядке:

- `Empty` — лист пустой, его перелистнули. Предыдущий рассматриваемый листок при этом не забывается.
- `Repeat` — лист не пустой и дословно равен последнему, который уже рассматривали. Рассматривают и сыгранный, и забракованный.
- `Unfit` — голос листок не принял. Теперь помнят именно этот лист.
- `Played` — голос принят и сложен с уже звучащей ночью перебором, не приписыванием в хвост.

Повтор проверяется раньше брака. Вторая копия негодного листка — это `Repeat`, а не ещё один `Unfit`.

Повтор сравнивает листок, каким его принесли, а не голос после снятого эха. Лист `(1, 2), (1, 9)` и лист `(1, 2)` звучат одинаково, но это два разных листа: оба `Played`. Сложенные сами с собой, они дают один удар `(1, 2)`.

Пустой лист между двумя одинаковыми повтор не отменяет. Лист `(5, 1)`, потом пустой, потом снова `(5, 1)` — это `Played`, `Empty`, `Repeat`.

Два сыгранных листа `(5, 1)` и `(2, 4)` в ночи лежат как `(2, 4), (5, 1)`: меньший колокол в паре слышно раньше. Приписать второй в хвост здесь будет ошибкой.

Длинную стопку, где эхо, передышка, повтор, брак и перебор встречаются вместе, смотрите в тесте `night / вся ночь`. Ответ в README не расписан нарочно: его собирают из правил выше.

## Как сдать

Работу сдавайте pull request в этот репозиторий, `ivashka27/rybinsk-night-peal`. Если открыть его в своём форке, в общий список он не попадёт.

1. Сделайте fork на свой аккаунт.
2. От `main` заведите ветку `solution/<github-login>`. В `main` форка решение не дописывайте.
3. Запустите тесты у себя. В отчёт попадёт сводка, в том числе если что-то ещё красное.
4. Запушьте ветку в свой fork.
5. Откройте pull request сюда: база `ivashka27/rybinsk-night-peal:main`, ветка — ваш `solution/<github-login>`.
6. Заголовок: `Рыбинск — Фамилия Имя`.
7. Текст возьмите из шаблона `.github/pull_request_template.md`.

В тексте нужны фамилия и группа, что успели, три короткие мысли из шаблона и последняя сводка тестов. Мысли пишите своими словами.

Во вкладке Actions форка один раз разрешите workflows. Проверка соберёт проект и запустит `./build/rybinsk_tests`. Локальный прогон всё равно нужен: в отчёт идёт его сводка.

В pull request не кладите `build/`, сгенерированный `ya.make`, дампы отладчика и чужие практики.
